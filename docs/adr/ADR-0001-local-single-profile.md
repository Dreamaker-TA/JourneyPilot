# ADR-0001：固定单一本地身份，不建账户系统

状态：已采纳
影响：`local_profile.py`、迁移 `0003_local_identity`、所有带 `user_id` 的表

## 决定

这个产品的身份是一个**常量**：`LOCAL_USER_ID = "local"`。没有注册、没有登录、没有
会话令牌。数据库里 `user_id` 列保留，但它的取值被迁移固定成这一个。

## 为什么

它是一个自托管的单人应用。之前那套「多用户预留」在实际运行中只产生了两种东西：
一批永远只有一行的表，和一批把 `user_id` 从请求体里读出来的接口 —— 而后者意味着
**客户端可以声明自己是谁**。在一个没有认证的产品里，那不是预留扩展性，是一个把
所有人的数据放在同一个可寻址空间里、并让调用方自己挑的接口。

## 替代方案与为什么没选

- **保留可选多用户**：需要认证才有意义，而认证是另一个产品。留一半等于留一个漏洞。
- **完全删掉 `user_id` 列**：那会让「以后要加」变成一次全表迁移。列留着、取值固定，
  代价只是每张表多一个常量列。

## 后果

- 服务端解析归属，**客户端不声明所有者**（知识库集合、记忆、偏好都是如此）。
- 想支持多人时，要先做认证，再放开这一列 —— 顺序不能反。
